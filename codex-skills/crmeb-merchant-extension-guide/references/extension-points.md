# 推荐扩展点

客户二开应优先通过扩展点增加能力，避免直接改核心流程。

## 新增接口

推荐路径：

```text
route/*
-> app/controller/*
-> app/validate/*
-> app/common/repositories/*
```

建议：

- 路由按入口放到对应文件。
- 控制器只做参数、权限、响应，不堆业务。
- 业务写到 repository。
- 复杂参数新增 validate。

## 新增业务事件

项目中大量业务通过 `event()` 扩展。推荐优先新增监听器，而不是直接侵入核心方法。

常见位置：

- `app/event.php`
- `crmeb/listens`

适合场景：

- 支付成功后发通知
- 订单创建后同步第三方
- 商品变更后清缓存
- 退款后触发客户自有逻辑

## 新增队列任务

耗时、可重试、不要求同步返回的逻辑应放到 `crmeb/jobs`。

适合场景：

- 第三方同步
- 批量处理
- 消息通知
- 图片处理
- 统计任务

## 新增定时任务

新增监听器并接入统一定时器事件。注意定时器只应注册一次，避免每秒重复注册业务 timer。

适合场景：

- 定期同步状态
- 超时订单处理
- 商品自动上下架
- 队列健康检查

## 新增第三方服务

推荐放到 `crmeb/services`，业务层通过依赖注入或 `app()->make()` 调用。

建议：

- 配置放 `config/` 或系统配置。
- 外部异常转换为业务可理解错误。
- 不在服务属性里长期保存请求态数据或原生连接。
