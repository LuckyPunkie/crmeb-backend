# 常见二开场景

## 新增后台接口

推荐步骤：

1. 在对应 `route/admin/*` 或 `route/merchant/*` 增加路由。
2. 新增或扩展 controller 方法。
3. 参数复杂时新增 validate。
4. 业务写入 repository。
5. 返回使用 `app('json')`。

验证点：

- 权限和登录态
- 参数校验
- JSON 返回格式
- 异常提示

## 新增订单创建后的业务

优先监听订单创建事件，不要直接改大量核心订单代码。

查找：

```text
event('order.create', ...)
event('order.create.before', ...)
```

适合处理：

- 同步客户 ERP
- 写客户自定义流水
- 发内部通知
- 给第三方系统推送订单

## 新增支付成功后的业务

优先监听支付成功事件。

常见事件：

- `pay_success_order`
- `pay_success_user_recharge`
- `pay_success_presell`
- `pay_success_meal`

验证点：

- 重复回调是否幂等
- 队列是否成功投递
- 支付金额和订单状态是否一致

## 新增订单字段

推荐步骤：

1. 数据库加字段。
2. 更新对应 model/dao/repository 写入逻辑。
3. 修改创建订单或更新订单的数据组装。
4. 修改列表/详情返回。
5. 补后台或用户端展示。

注意：

- 不要只改 controller 返回。
- 创建、查询、导出、打印、售后可能都受影响。

## 新增定时业务

推荐新增 listener，并在统一定时事件中注册。

注意：

- 定时器回调要注意 Swoole 协程和 Redis/PDO 连接。
- 不要在多个 worker 重复注册同一个任务，除非业务允许并发执行。
- 日志要能确认任务是否注册和是否执行。

## 新增通知/短信

推荐通过队列异步处理。

验证点：

- 模板配置
- 发送失败记录
- 重试策略
- 队列是否运行
